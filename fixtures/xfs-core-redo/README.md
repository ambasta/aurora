# Linux CORE recovery witness

Preserved 2026-10-29 bytes from a disposable 512 MiB image made by xfsprogs
6.13.0 and used by Linux 6.12.107. The producer overwrote existing prototype
files, fsynced and powered off without unmount. A private copy was then mounted
noatime, without an application writer, and cleanly unmounted. Linux logged
Starting/Ending recovery; xfs_repair -n returned zero afterward.

The original image SHA256 is
14786e316d191c2a399460a116952a773d197e52efec5c0c74ccc4f153c6c7c6;
the recovered image SHA256 is
d18b0b74c8aff92e5da9938dd13386f21bfa91c0d74d671e4e210f8c375ee7e7.
Before/after inode sectors are LBAs 99 and 100 (inode numbers 99 and 100).
The 176-byte native little-endian cores were extracted from complete committed
transactions in log records 2 and 5, after restoring cycle-stamped words.
The final inode-99 CORE is in record 5; inode-100 is in record 2.

After sectors are Linux output, not generated by Aurora or a Python replay
oracle. They preserve the file forks and record the recovered CRC and LSN.
These slices exercise pure conversion, not transaction admission, device writes,
crash atomicity or general journal recovery. hashes.json identifies decoded bytes.

The record headers and stamped payloads are also preserved. Record 2 has two
inode pairs (100 then 99), record 5 one (99); th_num_items counts the two logged
regions per pair. The decoder checks the complete transaction before returning
any selected pair. It uses the shared CRC implementation over the original
stamped bytes, then restores cycle words for decoding. Unused trailing payload
padding is opaque. Header identity, ring topology, allocation and live-log
membership are separate recovery-owner checks.

The owning-preflight test reconstructs a sparse image from the preserved root,
home inodes, all four canonical AGF/AGI/INOBT blocks from ../xfs-recovery-ag,
and seven leading log sectors. Original
inactive sectors 7..4097 are byte-identical stale-clear headers except their
physical LSN field; input construction substitutes that field. Sectors4098..131071
are zero. The full131072-sector log scan remains intact. Unrelated data and
allocation trees are omitted, so this sparse reconstruction is component input,
not a complete mountable filesystem. That original full-ring witness is retained
once. Focused negative/state cases use a clearly synthetic shortened log:
`logblocks=8` (64 sectors), active prefix 0..6, stale headers 7..15 and zero tail
16..63. The superblock CRC is repaired; homes, AG metadata and live records are
unchanged. Every declared log sector is still scanned by the unchanged product
and driver. These shortened sparse inputs are not Linux-valid filesystem media.
A separate whole original-image read-only run also matched the Linux planned
inode sectors; the complete device fixtures below remain unchanged.

Completion tests apply the returned home sectors and body/header records only to
a private byte copy. A body-only interrupted model is refused by the unchanged
read-only mount; the completed model returns the preserved64-byte hello and
9001-byte pattern files exactly. These are modeled sector replacements, not
NVMe writes, Flush ordering, power-loss atomicity or live authority handoff.

The exact body-only model is also re-entered through the recovery planner: full
preflight repeats and yields the same home/completion plan. Mutated padding,
cycle, location, duplicate orphan bodies, invalid old headers and torn homes
refuse with zero output. A completed-marker model revalidates metadata and
returns already_clean with no home/completion records; this still requires a
successful final Flush in the future device caller. No torn-state repair or
physical crash guarantees are inferred from these modeled inputs.

## Complete device-test inputs

`dirty.img.xz` preserves the complete original image above, not the sparse
component reconstruction. Its dirty journal was generated by Linux 6.12.107.
`completed.img.xz` is a static, reviewed **Aurora compatible-completion golden**:
only sectors 99, 100, 524335 and 524336 differ from the original. Its two home
sectors match the independently Linux-recovered `inode-*-after.hex` goldens.
Linux 6.12.107 independently mounted this completed image without replay, read
both files correctly and cleanly unmounted it; xfsprogs 6.13.0 accepted its
metadata (`xfs_repair -n`) and clean log. This is not the full Linux-produced
recovery image whose hash appears above. Do not regenerate the expected image
with the implementation being tested.

Both snapshots contain only the generated `hello` (64 bytes) and `pattern`
(9001 bytes) files: byte `i` is `(i * 37 + 11) % 256`. The isolated Linux producer
had no NIC or host mount. The root listing and both payloads were checked in
both snapshots. Each archive expands to 536870912 bytes; together they occupy
163544 compressed bytes. Default component tests use the small hex fixtures,
not these complete images. The archives make the opt-in device tests independent
of private retained paths, historical raw logs or a new Linux producer run.

### Decompress and run

From the repository root, in Bash, with the source compiler/build configured
as described in [the compiler guide](../../compiler/README.md#source-bootstrap),
set `BUILD` to that Meson build directory, `NVME_PREFIX` to the supported NVMe
model and `AURORA_BOOT_FIXTURE_PREFIX` to clean firmware (see
[device-test prerequisites](../../docs/xfs.md#reproducing-the-reference-media-gates)).
Allow space for the two decoded images and fresh private copies per run.

```bash
set -euo pipefail
work=$(mktemp -d)
xz -dc fixtures/xfs-core-redo/dirty.img.xz > "$work/dirty.img"
xz -dc fixtures/xfs-core-redo/completed.img.xz > "$work/completed.img"
printf '%s  %s\n' \
  14786e316d191c2a399460a116952a773d197e52efec5c0c74ccc4f153c6c7c6 "$work/dirty.img" \
  30ff484d5ac50f4b348ff689427391262ed616b38d999d62df012a5d4b87e1ab "$work/completed.img" \
  | sha256sum -c -
image=$(MESON_BUILD_DIR="$BUILD" scripts/kernel-image.sh uefi process-xfs-recover)
smoke=(python3 -B scripts/kernel_nvme_smoke.py --tool-prefix "$NVME_PREFIX" --run-only "$image")
"${smoke[@]}" --process-xfs-recover "$work/dirty.img" \
  --recovery-state dirty --output-dir "$work/dirty-run"
"${smoke[@]}" --process-xfs-recover "$work/completed.img" \
  --recovery-state clean --output-dir "$work/clean-run"
cmp "$work/dirty-run/storage.raw" "$work/completed.img"
cmp "$work/clean-run/storage.raw" "$work/completed.img"
```

The runner holds each regular-file input read-only, creates a fresh private
copy, and attaches only that copy writable. Never substitute a physical disk.
Keep the output directories for traces and whole-image deltas; every invocation
requires a fresh output directory.

### Completed-command interruptions and re-entry

Continue in the same shell. Each cut starts from the original dirty image and
compares its captured prefix with the static completed reference. Re-entry uses
the actual captured disk, not a recreated model. These are acknowledged-command
interruption tests in the supported NVMe emulator, not physical power-loss tests.

```bash
for pair in write-1:partial-99 flush-1:partial-both flush-2:orphan flush-3:clean; do
  cut=${pair%:*}; state=${pair#*:}
  "${smoke[@]}" --process-xfs-recover "$work/dirty.img" \
    --recovery-state dirty --recovery-cut "$cut" \
    --recovery-reference "$work/completed.img" --output-dir "$work/cut-$cut"
  "${smoke[@]}" --process-xfs-recover "$work/cut-$cut/storage.raw" \
    --recovery-state "$state" --output-dir "$work/reentry-$cut"
  cmp "$work/reentry-$cut/storage.raw" "$work/completed.img"
done
```

### Modeled prior writes and refusal inputs

The following optional inputs reproduce the separately qualified models. They
are byte replacements in private files, not observed interruptions or an XFS
recovery oracle. Partial homes use independent Linux home goldens already present
in the static reference; the orphan additionally has its completion body only.
The three refusal inputs damage the superblock magic, truncate the second live
record payload after its cycle word, or damage an inode home CRC, respectively.

```bash
for state in partial-99 partial-100 partial-both orphan \
             refused-early refused-late-record refused-torn-home; do
  cp --reflink=auto --sparse=always "$work/dirty.img" "$work/$state.img"
done
for spec in partial-99:99 partial-100:100 partial-both:99 partial-both:100 \
            orphan:99 orphan:100 orphan:524336; do
  state=${spec%:*}; sector=${spec#*:}
  dd if="$work/completed.img" of="$work/$state.img" bs=512 \
    skip="$sector" seek="$sector" count=1 conv=notrunc status=none
done
printf '\131' | dd of="$work/refused-early.img" bs=1 seek=0 conv=notrunc status=none
dd if=/dev/zero of="$work/refused-late-record.img" bs=1 \
  seek=$((524334 * 512 + 4)) count=508 conv=notrunc status=none
printf '\001' | dd of="$work/refused-torn-home.img" bs=1 \
  seek=$((99 * 512 + 511)) conv=notrunc status=none
for state in partial-99 partial-100 partial-both orphan \
             refused-early refused-late-record refused-torn-home; do
  expected=$state
  case "$state" in refused-*) expected=refused ;; esac
  "${smoke[@]}" --process-xfs-recover "$work/$state.img" \
    --recovery-state "$expected" --output-dir "$work/model-$state"
  if [[ $expected == refused ]]; then
    cmp "$work/model-$state/storage.raw" "$work/$state.img"
  else
    cmp "$work/model-$state/storage.raw" "$work/completed.img"
  fi
done
```

### Production console and one owner restart

With `NVME_GRAPHICS_PREFIX` selecting the separate NVMe/GOP model, the same
production image supports the explicit recovery rows. The owner-restart row
uses a private service payload: two real full mounts around one commit/exit
loss, not ordinary HostFiles continuity or unlimited remounts. It retains the
150-second deadline and finite nonreused command IDs.

```bash
scripts/watchdog.sh ninja -C "$BUILD" -j"$(nproc)" kernel-uefi-production \
  tests/graphical-terminal-host console-commit-hostile-aurora
production=(python3 -B scripts/kernel_production_smoke.py \
  --build-dir "$BUILD/kernel-images/uefi/production" \
  --renderer "$BUILD/tests/graphical-terminal-host" \
  --nvme-prefix "$NVME_GRAPHICS_PREFIX")
"${production[@]}" --xfs-image "$work/dirty.img" --xfs-recovery dirty
"${production[@]}" --xfs-image "$work/completed.img" --xfs-recovery clean
"${production[@]}" --xfs-image "$work/refused-late-record.img" --xfs-recovery refused
"${production[@]}" --xfs-image "$work/completed.img" --xfs-recovery clean --recovery-owner-restart
```
