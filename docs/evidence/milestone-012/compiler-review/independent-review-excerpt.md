# Existing independent compiler review excerpt

Copied from docs/review.md during evidence collection; no new review performed.


Reviewed the integration of closed nominal enums with Value-constrained composition and class-valued method results. Value accepts enums; Scalar and builtin array element constraints remain unchanged. Enum constants require a declared nominal type and an in-range named case. Generic scalar constants, numeric conversion, arithmetic and ordered comparison cannot create or reinterpret enum values. Exported signatures and specialization arguments retain direct-import/private-type checks; generated bodies receive only their fixed instance and exact nominal arguments, without expanding module reflection views.

Constructor calls with class arguments retain the private R11 argument record and R10 receiver. Class-returning methods instead save an independent R11 result destination, keep explicit scalar/enum arguments in registers, and save their receiver separately. These modes are exclusive. Result storage must be fresh, exact-type, live and disjoint from the receiver. Complete ReturnObject copies preserve recursive nominal layouts and logical initialization, including empty and private-array descendants. Existing copy/projection operations remain in use.

Independent combined testing passed on release compiler `a6de1e89e307b076672a1e2ee8a5e848625ac92e386622c1fa5fe7c6ab675026` and ASan/UBSan compiler `3c5272f7e8a32fdbd9561de88f6a7cede2fcd34d3cab7218f8e504faa07551b1`: 107 combined cases, comprising 44 native executions and 63 ordinary rejections, with alternate seed 39031 and 64 snapshot-model steps. Rejections preserved both absent and pre-existing output artifacts. A separate 64-case native ABI matrix passed on both compilers, covering every enum/scalar mask across six method arguments, six distinct nominal enum types, independent 64-leaf results and helper/division clobbering of hidden registers.

The DecimalAccumulator/DecimalResult suite independently passed 196 cases on each compiler: 130 native executions, 66 ordinary rejections and 2,676 Python-modeled decimal steps using seed 39031/256 steps. This checks full-width values, sticky error state, reset, copied reports and eager fallback evaluation. The public result constructor remains an explicit report constructor, not proof that parsing occurred. The historical composition suite passed 161 cases under the new sanitized compiler, including sixteen exact-site traps and 77 rejections; its updated count reflects the newly supported method-result behavior rather than reclassifying an old receipt.

All 592 direct IR cases passed independently with sanitized executable `1f8acd34a5a11340490ce174fff8b179b67477b77564ad943823aac3ef0b7064`. Ten exhaustive-dispatch controls, eighteen array-native checks/ten trap sites, eight composition-native checks and thirteen new enum/composed-result native checks passed. Nonrecovering address/undefined-behavior diagnostics remained enabled, with leak detection disabled for the documented environment limitation. No compiler defect was reproduced in this bounded integration scope. Kernel dispatcher review and milestone-wide final regression receipts remain pending and separate from these results.
