# Independent review of the isolated storage libraries

Reviewed the frozen `candidate-inputs.json` and `integration-delta.json` in this isolated workspace. Main Aurora and its M014 kernel/compiler inputs were not changed. The implementation uses release compiler `2d86780c0082d861e7031955737eef81bb36936c7971d5032b6a1abbb4a24bf8` and ASan/UBSan compiler `ca87388b07dd39207ab3342bed2b9cd4ad5212362b435289e7f97b93574476fa`; it adds no grammar, IR operation, driver or filesystem I/O.

The source review found no implementation defect in the bounded contract. The 16/32/64-bit endian readers validate nonnegative offset, minimum length and the remaining range before addressing bytes. Actual 16/32-bit results are widened u64 values with their corresponding ranges; the public result constructor does not enforce a narrower numeric type. CRC continuation checks the finalized prior value fits 32 bits before checking offset/count. Range checks use subtraction only after proving offset is within the span, so validation never forms an overflowing offset+count. Empty valid ranges preserve the prior finalized CRC. The reflected recurrence maintains a 32-bit remainder within u64, with all-ones initialization/final XOR and no unsigned wrapping dependency.

The XFS function first establishes exactly 512 bytes, magic, low-four-bit version 5, declared sector size 512 and sector logarithm 9. It checks the full sector with checksum bytes 224..227 replaced logically by four zero bytes; it does not omit those bytes or mutate the input. Stored CRC is little-endian while the four feature masks are big-endian. The version's upper bits and raw feature masks do not establish compatibility. A checksum-valid header with zero filesystem geometry or unknown feature bits deliberately still reports only `header_integrity_valid`. Public report constructors can fabricate status/data and confer no authority.

Pinned Linux reference files were independently fetched at commit `038d61fd642278bab63ee8ef722c50d10ab01e8f`: [xfs_cksum.h](https://github.com/torvalds/linux/blob/038d61fd642278bab63ee8ef722c50d10ab01e8f/fs/xfs/libxfs/xfs_cksum.h) blob `999a290cfd722b306c9944a61b8eeb4516f31b86` and [xfs_format.h](https://github.com/torvalds/linux/blob/038d61fd642278bab63ee8ef722c50d10ab01e8f/fs/xfs/libxfs/xfs_format.h) blob `9566a76233654004d54f47aac17ac60dd8a6629a`. Their field order and checksum convention agree with the narrow probe. No upstream implementation was added by this review.

Independent optimized-Python runs on both compiler pins passed 254 native cases and 1,702 API calls using seed 39059 and random-count 24. Expectations use complete 64-bit observations, Python endian decoding and whole-message GF(2) polynomial division. A separate SSE4.2 CRC32C cross-check matched that GF(2) oracle in 90 cases, covering lengths 0..4096 and arbitrary finalized 32-bit priors. This is supplemental oracle evidence on the review host, not a physical hardware qualification.

An additional 64 native cases passed on each compiler: 46 XFS profile/feature/corruption cases, sixteen arbitrary-prior continuation cases and two forged-report cases. The feature matrix exercises every bit position in each raw mask, including high bits. Tests observe all input bytes unchanged, full-sector corruption detection and invalid-prior precedence even when a forged success report contains u64 maximum. They deliberately demonstrate that recomputed CRC plus invalid geometry remains only a header-integrity fact.

The real offline fixture has SHA256 `55ad821909c312048d9936a74c8904cd25f97aa190b48ae0004b03eaffdc6586`. Its first-sector identity and the retained regular 512 MiB image hash were independently checked, along with the recorded xfsprogs executable and loaded-library hashes. A separate read-only `xfs_db -r -f` invocation exited zero and reported V5, sector size 512, sector logarithm 9, correct CRC and raw masks 0/0xf/0x2b/0. No mount, format, physical-device operation or image modification was performed by this review.

The raw stored checksum bytes are `c7 13 71 b6`. Their little-endian numeric value is `0xb67113c7`, matching GF(2) and native Aurora; xfs_db's displayed `0xc71371b6` must not be confused with that numeric value. Fifteen preserved-fixture observations passed independently on both compiler pins, with output redirected into separate review receipt directories rather than overwriting author evidence. Twelve additional real-fixture cases on each pin covered endian interpretation, zero-substituted full CRC, input preservation, corrupted bytes and deliberately rechecksummed unknown features/invalid geometry.

One fixture-harness weakness was corrected: compiler/fixture identity, exact length and oracle checks used Python assert and disappeared under optimization. They now raise explicitly. Optimized negative controls independently confirmed rejection of wrong compiler identity, wrong fixture identity and wrong length. Library modules were unchanged by that correction.

Generation provenance has one retained limitation: the original mkfs invocation's exit status was not separately captured, so it is explicitly null rather than reconstructed as success. Its recorded output, empty stderr, image/hash evidence and subsequent independent read-only xfs_db/native checks remain available. The review did not rerun mkfs to replace that history.

No unresolved reproduced library defect remains within this scope. Candidate source/test manifest hashes stayed unchanged. This supports the recorded readonly decoding, checksum and header-fact behavior; it does not establish full XFS validation, mount support, feature compatibility, journal recovery, writable access, durability, authentication or NVMe I/O. Integration should apply only the explicit delta and retained evidence, without replacing unrelated newer files.

The final offline driver subsequently gained explicit compiler/hash and receipt-output options. Both final CLI runs were independently repeated under optimized Python and passed fifteen observations on each pin; their JSON receipts include the final driver hash. The author's separate initial sanitizer fixture attempt lacked the established leak-detector setting and failed under tracing before executing native cases. That failed attempt remains recorded; the successful author and independent runs use the previously established `detect_leaks=0:halt_on_error=1` environment, without disabling fatal address/undefined-behavior diagnostics.
